Three approaches to build it

Same story, same animations, same visual language. The difference is how we architect it and how much we replace.

A

Story Takeover — Replace the entire card

When uc-00 is active, ResponseCard renders a completely new NCEStoryCard component instead of the current layout. The story card owns its own scene management, scroll tracking, and animation orchestration.

Pros
• Total creative freedom
• Clean separation — no fighting existing layout
• Can be the template for other use cases later
Cons
• Biggest build — new component from scratch
• Need to handle all the card infrastructure (resize, context, etc.)
Kills: NCEStackedBars, CompanionViz (treemap+trend), ContractorDrilldown table, KPI boxes, UseCaseAnswer text block — all replaced by story beats
B

Story Layer — Overlay on existing card

The story plays as an animated overlay on top of the card. When it finishes (or user dismisses), the traditional card is underneath as a reference. Think of it as a "guided tour" that plays first, then gets out of the way.

Pros
• Safer — existing card untouched
• User can skip to raw data
• Easier to A/B test
Cons
• Compromised vision — story + old card fighting for attention
• "Skip" option undermines the narrative
• Two experiences to maintain
Keeps: Everything. Story is additive, not a replacement.
C

Story-First with Data Drawer

The story IS the card — full replacement like option A. But at the end of the story (after beat 5), a subtle "View raw data" affordance slides open a compact data drawer with the essential numbers in a clean table. The story is primary; data is secondary reference.

Pros
• Full creative freedom for the story
• Data-minded users still have an escape hatch
• Story doesn't compete with charts
• Clean architecture — story component + minimal data component
Cons
• Still a big build (story + drawer)
• Drawer needs its own design to not feel like an afterthought
Kills: Same as A — all current viz components. Adds: Collapsible data drawer at the end.
My recommendation
Option C — Story-First with Data Drawer. You get the full narrative experience without compromise, but the analytical users who want to copy a number into an email still have a way. The drawer is a footnote, not a co-star.
