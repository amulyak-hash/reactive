Three Approaches for the Intelligence Constellation

Same dark glowing aesthetic — different information architecture. Click to expand in-place for all three.

A — Entity Network

Nodes = real things (contractors, EWs, NCEs, packages). Connections = real relationships. Hub stays as programme. Node size = exposure. Color = severity/type.

Pros: True intelligence network — every line means something. Naturally shows which contractors are "hot."
Cons: Can get dense with many entities. Needs careful filtering/clustering.

B — Concentric Rings

Organized by entity type in rings: centre = programme, ring 1 = contractors, ring 2 = packages, ring 3 = events (EWs, NCEs). Connections flow inward. Density = risk.

Pros: Clear hierarchy — you always know what "level" you're at. Scales cleanly.
Cons: More structured = slightly less organic. Relationships between same-ring entities harder to show.

C — Gravity Well

Position = risk. Force-directed layout where problematic entities cluster together in a "hot zone." Healthy entities drift to the periphery. The spatial pattern is the insight — dense center = trouble.

Pros: The most powerful "aha" — you literally see risk clustering. Layout itself tells the story.
Cons: Force-directed layouts can be jumpy/unpredictable. Harder to find a specific entity.

💡 Recommendation: A (Entity Network)

Best balance for a demo tool — familiar constellation aesthetic, but every element is real and meaningful. The "aha" comes from seeing that Afcons has 3 early warnings and 14 NCEs radiating from it while L&T is clean. Connections tell a story without needing explanation. B is too structured for a demo wow-factor. C is the most powerful insight-wise but force-directed layouts are unpredictable and harder to animate reliably.
